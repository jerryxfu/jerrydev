My own notes for running language models on my laptop, with no account and no network. A MacBook Air M5 with 16 GB of
RAM, and [Ollama](https://ollama.com) from Homebrew. Correct as of October 2026.

Ollama serves the models over an OpenAI compatible API at `http://localhost:11434`. Only one model sits in memory at a
time. It swaps on demand, and unloads after about 5 minutes of idling.

## Install

```bash
brew install --cask ollama
```

Then launch the Ollama app. The menu bar icon starts the server. To run it headless instead:

```bash
ollama serve
```

## My models

The left column is the nickname I made, not the name you pull. The aliases are set up in
[A nickname and a bigger context](#a-nickname-and-a-bigger-context).

| Nickname | Model | Context | For |
| --- | --- | --- | --- |
| `wrn3-7b` | WhiteRabbitNeo V3 7B | 16K | Security and CTF work. Security tuned and low refusal |
| `qwen3-14b` | Qwen3 14B, abliterated | 8K | Main chat model, for ideas and projects. About 14 tokens/sec, about 10 GB in memory |
| `qwen3-8b` | Qwen3 8B, abliterated | 16K | Lighter and faster. The fallback when other apps need the RAM |

<Callout kind="note">
**Abliterated** is an instruct model with its refusal behaviour surgically removed, so it answers instead of saying it
cannot help with that.
</Callout>

## Pull the models

```bash
ollama pull hf.co/bartowski/WhiteRabbitNeo_WhiteRabbitNeo-V3-7B-GGUF:Q4_K_M
ollama pull huihui_ai/qwen3-abliterated:14b
ollama pull huihui_ai/qwen3-abliterated:8b
```

<Callout kind="tip">
Pulls are resumable. If one dies with `unexpected EOF` on a flaky network, run the same line again and it carries on
from where it stopped.
</Callout>

## A nickname and a bigger context

Ollama's default context is only 4K, so each model goes through a tiny Modelfile that sets a longer one and gives it a
short name. The 14B at 8K:

```text
# Modelfile
FROM huihui_ai/qwen3-abliterated:14b
PARAMETER num_ctx 8192
```

```bash
ollama create qwen3-14b -f Modelfile
```

The alias reuses the same weights on disk, so it costs no extra space. That is also why `ollama list` shows both the
alias and the model it came from. Same data, listed twice.

## Commands

| Command | Does |
| --- | --- |
| `ollama run <name>` | Start a chat |
| `ollama list` | List installed models |
| `ollama ps` | What is loaded in RAM, with the keep alive countdown |
| `ollama stop <name>` | Unload a model from memory now |
| `ollama pull <ref>` | Download a model |
| `ollama rm <name>` | Delete a model or an alias |
| `ollama cp <old> <new>` | Copy a model. To rename, copy then remove the old one |
| `ollama show <name> --modelfile` | Print a model's definition |

Inside `ollama run`:

| Type | Does |
| --- | --- |
| `/bye` | Exit |
| `/set system "..."` | Set a system prompt or a persona |
| `/set nothink` | Turn off Qwen3's reasoning output, for quick answers |
| `/?` | Help |

## Config

Environment variables, read by the server:

| Variable | Does |
| --- | --- |
| `OLLAMA_KEEP_ALIVE=30m` | How long a model stays in RAM. `0` unloads right away, `-1` keeps it forever |
| `OLLAMA_MAX_LOADED_MODELS=1` | Keep one model resident. What I use on 16 GB |
| `OLLAMA_HOST=0.0.0.0:11434` | Serve on the local network, to reach it from another device |

```bash
export OLLAMA_KEEP_ALIVE=30m
ollama serve
```

## Call it from code

```bash
curl http://localhost:11434/api/generate -d '{"model":"qwen3-14b","prompt":"hello","stream":false}'
```

There is an OpenAI compatible endpoint at `http://localhost:11434/v1`. The API key is never checked, so any string
works, and the model is the nickname:

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="local")
answer = client.chat.completions.create(
    model="qwen3-14b",
    messages=[{"role": "user", "content": "hello"}],
)
```

## Gotchas

- One model loads at a time. Switching nicknames costs a few seconds of reload.
- 16 GB is tight for the 14B and it leans on swap. Close the heavy apps, Xcode first. The 8B is the comfortable
everyday option.
- Qwen3 thinks out loud before answering. `/set nothink` stops that.
