Ce cours explique comment le robot *voit* : comment une caméra transforme le monde en pixels, comment on retrouve des
AprilTags dans ces pixels, comment quatre coins de tag deviennent une position sur le terrain, et ce que l'équipe fait pour
que cette position reste fiable quand le robot bouge vite et que l'éclairage change. La dernière leçon est pratique : régler
les Limelight, avec un aide-mémoire pour ne pas avoir à tout retenir.

## 2. Le problème : où est le robot?

Le robot sait à peu près où il est grâce à l'*odométrie* : les encodeurs des roues et le gyroscope lui disent de combien il
a avancé et tourné depuis le départ. Le problème, c'est que ces erreurs s'accumulent. Une roue qui glisse, une collision, et
la position estimée dérive sans que rien ne la ramène vers la réalité.

Les AprilTags sur le terrain sont des repères fixes dont la position exacte est connue. Chaque fois qu'une caméra en voit
un, elle peut recalculer la position absolue du robot et corriger la dérive. C'est ce qu'on appelle la *localisation par
vision*, et c'est le fil conducteur de tout le cours : chaque leçon ajoute une étape de la chaîne qui va des pixels à la
position sur le terrain.

## 3. Comment le cours est organisé

Le cours a deux parties, plus une étagère de références.

**Computer vision** est le cœur du cours. Les leçons se lisent dans l'ordre; chacune suppose la précédente.

1. [Caméras et images](/blog/vision-cameras) : le modèle sténopé, l'exposition, le gain, la calibration.
2. [Les AprilTags](/blog/vision-apriltags) : ce qu'ils encodent et comment le détecteur les trouve.
3. [L'estimation de pose](/blog/vision-pose-estimation) : le problème Perspective-n-Point et l'ambiguïté qui vient avec.
4. [Localisation robuste](/blog/vision-localization) : fusionner odométrie et vision, et ce que notre code fait de plus.
5. [Régler les Limelight](/blog/vision-limelight-tuning) : la leçon pratique.

**Artificial intelligence** est la partie « pour les curieux », en anglais. Elle n'est pas nécessaire pour comprendre la
vision sur le robot, et à peu près rien de ce qu'elle contient n'est utilisé dans notre contexte. Elle existe parce que les
questions reviennent à chaque formation : c'est quoi un réseau de neurones, comment un détecteur d'objets fonctionne,
comment ChatGPT fait ce qu'il fait.

**Tools** contient les aide-mémoire : [Limelight](/blog/cheatsheet-limelight), [repères et
conventions](/blog/cheatsheet-coordinates), [maths](/blog/cheatsheet-math) et la [checklist de
débogage](/blog/cheatsheet-vision-debug). Ce sont les pages qu'on rouvre pendant la saison.

## 5. Conventions

Les leçons de vision et les aide-mémoire sont en français; le chapitre *Artificial intelligence* est en anglais. Dans les
deux cas, les termes techniques restent **toujours en anglais**, en italique la première fois (*pose estimation*, *axis
aligned bounding box*), parce que c'est sous ce nom qu'on les retrouve dans la documentation, le code et les forums, et
que les traduire donne des choses étranges. Une traduction française n'apparaît que si elle aide.

Les encadrés ont chacun un rôle :

<Callout kind="note">
Une précision ou un rappel qui ne casse pas le fil de la lecture.
</Callout>

<Callout kind="tip">
Un raccourci, une astuce, une façon de vérifier quelque chose rapidement.
</Callout>

<Callout kind="warning">
Une erreur fréquente ou un piège.
</Callout>

Les blocs de code sont en Java quand ils parlent du robot et en Python quand ils servent à expérimenter.
