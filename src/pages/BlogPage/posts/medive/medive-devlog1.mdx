Before the numbers, a quick tour of what they're about. The full definitions are in [MEDIVE reference sheet](/blog/medive-reference).

### What a patient looks like

DDXPlus patients consists of a list of coded *evidences* (symptoms and antecedents), plus an age, a sex, one true pathology out of 49, and a *reference differential* which are the diseases the dataset considers plausible for that patient, each with a probability.
The evidences are then turned into a short note by us with handwritten templates. That note is the only thing the text models ever see.

The scores against the true pathology (ACC) ask whether the models put "{stats.sample.label}" on top. The differential scores (DDR) ask how much of that longer list the models surfaced.

### The models

Every model gets the same note and returns a ranked list of the 49 diseases. The difference is in how they process the text. Models names: **B** is a baseline, a cheap or theoretically perfect reference. **M** is a model with a learned representation. [More details on the models →](/blog/medive-reference#the-models)

**B-class: the baselines.** Each one turns the note into a bag of simple features and hands it to logistic regression, one weight per feature per disease.

- **B0, keyword match.** Knows a fixed list of symptom names and scans the note for a close match to each. RapidFuzz tolerates typos. The output is a yes-or-no per name. This is the basic symptom checker the project argues against: the model will completely miss a patient who says the same thing in other words.
- **B1, TF-IDF.** Counts every word and every pair of neighbouring words, weighted so that words found in most notes count for little. This is the standard strong baseline for any text task. It has no idea what words mean, but it can still find patterns.
- **B2, the oracle.** Does not read the note. It gets the true evidences straight from the dataset, essentially reading from the answer sheet. It marks the top of the ruler, so whatever it can't do, the other models can't do either.

**M-class: learned representations.** Each one ends in a small neural network (a one-hidden-layer MLP) trained on tier 0 only.

- **M1, SapBERT text-only.** A frozen biomedical language model reads the note, turns each word piece into 768 numbers, and averages them into one vector per patient. Only the small classifier on top learns. This is the text half of the hybrid.
- **M2, concepts only.** A dictionary tool (QuickUMLS) finds medical concepts in the note and returns their standard codes, CUIs. Each code gets a learned vector of 128 numbers, and those are averaged. This is the concept half of the hybrid.
- **M3, the hybrid.** M1's 768 numbers fused with M2's 128, with the same classifier on top. This is the model the whole project is about.
- **Soft-target** is a training setting, not a model. M1 soft-target and M3 soft-target are trained to surface the whole reference differential instead of putting the one true disease on top.

### The four versions of the text

The test patients never change. Only the words do. Models train on tier 0 only, so tiers 1 to 3 are wording they never saw. [The tiers →](/blog/medive-reference#the-four-tiers)

- **Tier 0, clean.** The templated note as written above.
- **Tier 1, synonyms.** Symptom names swapped for UMLS's own alternative names. Optional, and a bit circular since the concept pathway uses the same vocabulary.
- **Tier 2, lay language.** Symptom names swapped for everyday wording: "a belly that feels blown up like a balloon" for a bloated, distended abdomen. Two rewordings per symptom written by me, none of them in UMLS. This is the "realistic" case.
- **Tier 3, typos.** Letters swapped, dropped or transposed inside the symptom phrases, about one edit per ten characters. The extreme test.

### The scores

Each patient has one true disease and one reference differential. Every condition runs on five random seeds. [More details on scores →](/blog/medive-reference#the-scores)

Against the true disease:

- **Acc@k.** Is the true disease in the model's top k? Reported for k = 1, 3 and 5. Acc@1 is plain "accuracy".
- **MRR.** Mean reciprocal rank. First place scores 1, second place 1/2, third 1/3, averaged over patients. It rewards putting the right answer near the top even if it isn't first.
- **Macro-F1.** The F1 score at rank 1, computed per disease and averaged with equal weight. A rare disease counts as much as a common one, which plain accuracy doesn't account for.

Against the reference differential:

- **DDR@5.** Differential recall. Of the diseases on the reference list, how many made it into the model's top five? It has a ceiling of 65.7 percent on this test set, because the reference list has about nine entries and five slots can't hold nine. **DDR@10** is the same thing with ten slots.
- **DDP@5.** Differential precision. Of the model's top five, what share is on the reference list. High DDR with low DDP means the model found the list by guessing widely.

We can notice a few things:

### 1. Clean text is too easy to tell the models apart

The oracle (perfect model) scores 99.7 at rank 1, and the basic baselines are within a point of it. Every model puts the true disease in its top three, every single time. The question about relevance on clean text is going to be a tie, but that wasn't a surprise, since it's close to being the "perfect" scenario.

### 2. The differential diagnosis list is where one stands out

Every standard model here was trained to predict only the one true pathology, and each of them recovers somewhere between a third and 40 percent of the differential list. On the other hand, the soft-target model that was trained on the full list instead of the single true disease reaches 59.3 (the ceiling is 65.7) at the cost of Acc@1, which drops to 75.8. We can see that the quality of the results follows what we ask the model to learn.

<img className="diagram" src={_figTypoDrop} alt="Acc@1 and DDR@5 per condition, clean versus typos, with the SapBERT conditions dropping the most" />

With typos, word counting still sees all the hundred other words, and fuzzy keyword matching forgives spelling by design, whereas SapBERT does neither, so it loses about four points at rank 1, where the baselines lose half a point or nothing.

The bigger drop is with M1 soft-target: 75.8 clean, 51.0 with typos, which is a loss of 25 points. It's the same model as M1, but what's different is the training goal. The soft-target model was trained to spread its probability across a whole differential diagnosis, so its top choice sits only slightly above the second and third. A typo translates to a small nudge to the input vector, and a small nudge is enough to flip which disease comes first. The single-label M1 was trained to put one disease far ahead of the rest (confidently), so the same nudge rarely changes the winner.

The right panel of the graph above explains this well. Looking at the differential scores, every standard model sits at around the same, much lower score: B0 at 40.1, B1 at 39.5, the oracle at 39.0, M1 at 34.4. Even the oracle, which reads the answer sheet, doesn't get past 40. The soft-target model starts at 59.3, drops about five points down to 54.5 with typos, and it's *still* fourteen points above the best of the others on *clean* text.

So the rank-1 pick is quite sensitive, not the list used for differential diagnosis.

## Poking around SapBERT's space

Here are a few more interesting pictures, because why not. These probably won't go in the essay, but each of them taught me something about the model I'm building on.

### The 49 diseases

SapBERT has never been told what our 49 pathologies are, and yet it already places most of them sensibly, with related diseases close to each other. There are two ways to look at this.

The first way is to give it the 49 pathology *names* and nothing else, which is close to what it was actually trained for. SapBERT turns each name into 768 numbers, and PCA (principal component analysis) reduces those down to two so they can be drawn as the map below. PCA keeps the two directions in which the names are the most spread out, and flattens all the others. Here, those two directions only hold {(space.views_spread.pca_variance_kept_names * 100).toFixed(0)} percent of the spread. In other words, two names that look close on the map can still be far apart in the dimensions that got flattened. What PCA can't do is invent a cluster that isn't there, since all it does is rotate and flatten.

<img className="diagram" src={_figDiseaseNames}
     alt="The 49 DDXPlus pathology names as SapBERT embeds them, PCA to two dimensions, one fixed colour per pathology" />

Names that share a word sit together: "stable angina" next to "unstable angina", the two rhinosinusitis, bronchitis next to bronchiolitis, and the two neoplasms off on their own. That's what SapBERT's training taught it: names that mean similar things belong close together, and names that share a word are the easiest case of that.

The second way is to use the patient notes instead. Each note becomes one vector, which is what the classifier works with, and all the notes of one pathology are then averaged into a single point. To get both views onto one map, the two clouds of points were aligned using Procrustes analysis (center both clouds, scale both, then keep the rotation that lines them up best).

The left panel below shows the notes sitting on the name map. The right panel draws one line per disease, from where its name sits to where its patients sit. Essentially, the right panel compares how the model understands a disease's name with how it understands the notes of the patients who have it.

<img className="diagram" src={_figDiseaseMaps}
     alt="Left: the 49 note centroids rotated onto the name map. Right: a line per pathology from its name position to its note position, the ten longest labelled" />

Even after the best possible rotation, the two clouds don't perfectly overlap. On a scale of 0–2, where 0 means the same arrangement and 2 means nothing in common, we get {space.procrustes.disparity.toFixed(2)} here. Another way to measure it: on average, only {(space.views_agree.mean_neighbour_overlap * 100).toFixed(0)} percent of a pathology's five nearest neighbours are the same in both views. So basically, the two views disagree about most of the neighbourhood.

The pathologies that move the least are the ones whose wording and symptoms agree: {space.procrustes.least_moved.slice(0, 3).map(m => m[0]).join(", ")}. The ones that move the most are {space.procrustes.most_moved.slice(0, 3).map(m => m[0]).join(", ")}, and there is a reason for that, which shows up further down in "A region that shouldn't exist".

The two views differ because of what each point is made of:

**A dot in the name view is one short phrase.** Just a few words each, with nothing shared and nothing averaged. SapBERT was trained to pull different names of the same concept together, so two dots that are close have a more similar meaning than two dots far apart. That closeness is measured with cosine similarity, where 1 means the two vectors point the same way and 0 means they're unrelated. The names are fairly spread out, with an average similarity of {space.views_spread.names_pairwise_cosine_mean.toFixed(2)}, and the two least alike names score only {space.views_spread.names_pairwise_cosine_min.toFixed(2)}.

**A dot in the note view is an average of averages.** Each note is the mean of about {stats.wordpiece.pieces_mean_clean.toFixed(0)} word-piece vectors, and each pathology is then the mean of hundreds of those notes. That gives one dot per disease, called its centroid. On top of that, every note shares the same template skeleton: "year-old patient", "presents with", "pain intensity", "travel out of the country". So all 49 centroids end up packed close together: the average pair scores {space.views_spread.notes_pairwise_cosine_mean.toFixed(2)}, and even the two *least* alike still score {space.views_spread.notes_pairwise_cosine_min.toFixed(2)}. Since the skeleton is the same in every note, it can't tell two diseases apart, and what's left to separate them is the symptoms. So this view groups diseases by what the patients say.

By the notes, they score {space.closest_note_pairs[0][2].toFixed(3)}, which is almost identical, because their patients describe the same blocked nose and the same facial pain.

#### Why that makes some sense, actually

PSVT is the clearest case. It stands for paroxysmal supraventricular tachycardia, which is a type of abnormal, rapid heart rhythm that starts suddenly and then stops on its own after some time. Paroxysmal means "sudden", supraventricular means "above the ventricles" (the lower chambers of the heart), and tachycardia means "fast heart rate".

By the notes, it sits next to panic attack, since both are reported as a racing heart, chest discomfort and a frightened patient, and that's a confusion a real clinician would recognise.<br/>
By the name, it sits with the anginas and NSTEMI (a specific kind of heart attack). All SapBERT has to go on there is the four letters "PSVT". It most likely learned during training that this abbreviation names a heart condition, so it places it among the other heart conditions in the list. But atrial fibrillation, the other heart-rhythm problem in the list, isn't among its three closest. So the name view knows "heart", but not much about what kind of heart problem.

Pneumonia splits the same way:<br/>
By the notes, it lands with the whole-body illnesses, influenza, HIV and SLE (lupus), which all bring fever, fatigue and aches.<br/>
By the name, it lands with anything to do with the lungs and airways: bronchiolitis, bronchitis and a lung tumour.

Stable angina is the one case where the two views agree, because the diseases that share its wording happen to share its symptoms too.

So the note view is what the classifier gets to use. The classifier is the small neural network on top of SapBERT that takes a patient's vector and picks a disease, and what it sees is mostly the symptoms, since the template sentences are the same in every note. The name view is closer to the ontology's view, meaning the way UMLS (the big medical dictionary SapBERT was trained on) organises diseases by their names. That's roughly what the concept half of M3 is supposed to add, since a concept code is closer to a name than to a note. But whether that actually helps M3 is the whole question.

The bright squares are the rhinosinusitis pair and the angina family, and that's exactly where the circles land. Across all of M1's rank-1 errors on this tier, {space.confusions.share_to_top5_neighbour.toFixed(0)} percent go to one of the true pathology's five nearest centroids. For comparison, five diseases out of 49 is about a tenth of the list, so a model guessing at random would only put about a tenth of its errors there. Essentially, when the model is wrong, it's mostly wrong in the direction the space was already leaning.

So why do these particular pairs overlap? Here's my lay reading of it: I'm reading the dataset's symptom lists, not giving a clinical opinion.

- **Chronic and acute rhinosinusitis.** This is the biggest one, and it goes both ways. Rhinosinusitis means inflamed nose and sinuses, so both come with a blocked nose, facial pain or pressure, discharge and a dulled sense of smell. What separates them is *duration*, weeks for acute versus months for chronic, and a snapshot note has no duration in it. No amount of careful reading fixes that, because the information simply isn't in the text.
- **Stable angina, unstable angina, NSTEMI/STEMI.** The same chest pain coming from the heart's blood supply, at three levels of urgency. What tells them apart is *when* the pain arrives (with effort and settling with rest, or at rest and getting worse), and whether the heart muscle is actually being damaged. That last part takes an ECG and a blood test to know. None of it is in a symptom note, and clinicians don't separate these three from the history alone either. That's what the tests are for.
- **Bronchitis, spontaneous pneumothorax, and GERD.** Bronchitis is an inflamed airway, so a cough plus chest discomfort. A pneumothorax (from "pneumo", air, and "thorax", chest) is air leaking around a lung, so sudden chest pain and breathlessness. Acid reflux brings chest pain, a burning feeling and often a cough. So all three arrive with the chest words and little else. GERD is also one of the ten most frequent classes in the test set, which makes it the model's safe bet when the chest words are there and the rest is scrambled.
- **Boerhaave and GERD.** Boerhaave syndrome is a torn oesophagus after violent vomiting, named after the Dutch doctor who first described it. GERD is the same organ, complaining much more mildly. Both notes carry vomiting and pain in the chest or the upper belly.
- **Acute laryngitis, viral pharyngitis, URTI.** The larynx is the voice box and the pharynx is the throat, so these are three names for a viral infection of the same few inches of throat. All three give a sore throat, a hoarse voice, a cough and a bit of fever. Real triage lumps them together too.

The pattern is the same each time. A confused pair is either:

- one disease caught at two different stages, or
- two neighbouring organs whose notes share the same pain descriptions.

In both cases, the one fact that would decide between them (a duration, a test result, a precise location) is either missing from the note or sits in a single clause. And a single clause is exactly what a few typos can erase. Whether these count as "reasonable" confusions is the error-analysis question for the essay, and it needs someone with clinical training to settle it.

### A region that shouldn't exist

Back on the heatmap above, there's a block of {space.short_note_block.n} pathologies in the bottom-right corner, and they stick to each other and away from everything else. The members are {space.short_note_block.members.join(", ")}.

Some of those do belong together, since croup, bronchiolitis, whooping cough and laryngospasm are all airway diseases, mostly in children. But atrial fibrillation next to Ebola next to Guillain-Barré (a nerve disorder that causes weakness in the limbs)? Nothing medical joins those three. So I went looking for what else they had in common.

<img className="diagram" src={_figDiseaseRegion}
     alt="Scatter of the 49 pathologies: mean evidences per patient on the x axis, mean similarity to the other 48 pathologies on the y axis, showing two separate bands" />

It turns out to be note length:<br/>
Patients in that block have about {space.short_note_block.block_mean_evidences.toFixed(0)} evidences each, against {space.short_note_block.rest_mean_evidences.toFixed(0)} for everyone else.<br/>
So their notes run about {space.short_note_block.block_mean_words.toFixed(0)} words, against {space.short_note_block.rest_mean_words.toFixed(0)}.

A short note is mostly template: the age line, "presents with", a couple of clauses and that's it. Average that into one vector, and those notes end up looking more like each other than like any long note, whatever disease they describe. The plot above shows it as two separate bands with nothing in between, and the whole block sits in the lower one.

Age isn't the explanation, by the way, even though it's the obvious suspect with this many childhood illnesses. Both are negative because a bigger gap means less similar, and the note-length one is much stronger.

This is also the reason promised earlier. The diseases that moved the most between the name view and the note view are in this block too: {space.procrustes.most_moved.slice(0, 3).map(m => m[0]).filter(n => space.short_note_block.members.includes(n)).join(", ")}. Their notes sit close to other short notes, wherever their names happen to be.

This is worth knowing for two reasons:

- **It's built into M1.** It comes from averaging the word pieces together, so it will be in M1's features no matter which classifier sits on top.
- **Some neighbours are only neighbours by length.** A few of the confusions in the section above are between diseases that sit together because their notes are short, not because they're alike.

## Where M1's four points go

### Looking inside the language model

BERT-family models and basically every Large Language Model (LLM) read *word pieces*, not words. The tokeniser is the step that cuts the text into those pieces before the model reads anything. The one used by SapBERT is called WordPiece, and it carries a fixed vocabulary of about thirty thousand pieces. Any word that isn't in that vocabulary gets split into the longest pieces it does know. A clean medical word is usually one piece, whereas a misspelled one won't be recognised at all. Here's SapBERT's own tokeniser on words from patient `test_12`, clean on the left, tier 3 on the right:

| Clean | Pieces | Typo | Pieces |
| --- | --- | --- | --- |
| significantly | `significantly` | signifcantly | `sign` `##if` `##can` `##tl` `##y` |
| cough | `cough` | couhg | `cou` `##hg` |
| symptoms | `symptoms` | sypmtoms | `sy` `##pm` `##to` `##ms` |
| heavy | `heavy` | hevay | `hev` `##ay` |

The `##` marks a piece that continues the previous one. Those fragments were never learned as "significantly" or "cough", so their vectors have nothing to do with the word the patient meant:<br/>
"cough" is one piece the model knows well.<br/>
"couhg" becomes `cou` and `##hg`, two fragments that have nothing to do with coughing.

M1 averages every piece's vector into one vector per patient, so every corrupted word pulls that average a bit off course.

The fragments also make the note longer: {stats.wordpiece.pieces_mean_clean.toFixed(0)} pieces on average at tier 0, against {stats.wordpiece.pieces_mean_typos.toFixed(0)} at tier 3. SapBERT reads all of it, so nothing gets cut off the end. In other words, the whole cost of a typo is that one word's vector goes wrong, and that word gets averaged with about a hundred other words that are still fine. That's why the damage is four points and not a collapse, and why tier 3 basically tests the tokeniser and the averaging, nothing else.

### One word, one edit at a time

This is the WordPiece story in its simplest form. Take a symptom word, apply one random character edit, then another, and so on. After each edit, measure how far its vector has moved from the clean word's vector. That's the cosine distance, where 0 means it hasn't moved at all and bigger means further away. The result is averaged over {space.word_typos.trials} random edit paths.

<img className="diagram" src={_figWordTypos}
     alt="Left: cosine distance of a word from its clean form against the number of character edits. Right: number of word pieces the tokeniser produces" />

The first edit does most of the damage: a mean distance of {space.word_typos.distance_after_1_edit_mean.toFixed(2)} after one edit, and still only {space.word_typos.distance_after_3_edits_mean.toFixed(2)} after three. The right panel shows why:<br/>
A clean word is one piece.<br/>
After one edit, it's two, three or four pieces that have nothing to do with the original.

After that, more edits barely matter, because the word is already gone. For comparison, a whole note only drifts about {stats.drift_mean.toFixed(2)} on the same scale, as the next section shows. One word gets wrecked, but the note it sits in barely moves.

## What got decided since devlog #0

A few things got settled in the two weeks since the plan, all of them before the hybrid model even exists. That's on purpose: it's a lot harder to fool yourself when the rules are written down first.

- **Two training goals, reported separately.** A model can learn to put the one true disease on top, or it can learn to reproduce the whole reference differential (that's soft-target). Every hybrid result will be reported under both.
- **DDR@10 joins the scores** as a secondary metric, since the reference differential has about nine entries and five slots can't hold nine diseases.
- **Two comparisons are locked:** hybrid vs text-only, and hybrid vs TF-IDF, each on clean text, lay language and typos. Locking them now stops me from picking whichever comparison happens to look best later.
