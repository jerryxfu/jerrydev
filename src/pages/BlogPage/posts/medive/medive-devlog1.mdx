Before the numbers, a quick tour of what they're about. The full definitions are in [MEDIVE reference sheet](/blog/medive-reference).

### What a patient looks like

DDXPlus patients consists of a list of coded *evidences* (symptoms and antecedents), plus an age, a sex, one true pathology out of 49, and a *reference differential* which are the diseases the dataset considers plausible for that patient, each with a probability.
The evidences are then turned into a short note by us with handwritten templates. That note is the only thing the text models ever see.

### The models

Every model gets the same note and returns a ranked list of the 49 diseases. The difference is in how they process the text. Models names: **B** is a baseline, a cheap or theoretically perfect reference. **M** is a model with a learned representation. [More details on the models →](/blog/medive-reference#the-models)

**B-class: the baselines.** Each one turns the note into a bag of simple features and hands it to logistic regression, one weight per feature per disease.

- **B0, keyword match.** Knows a fixed list of symptom names and scans the note for a close match to each. RapidFuzz tolerates typos. The output is a yes-or-no per name. This is the basic symptom checker the project argues against: the model will completely miss a patient who says the same thing in other words.
- **B1, TF-IDF.** Counts every word and every pair of neighbouring words, weighted so that words found in most notes count for little. This is the standard strong baseline for any text task. It has no idea what words mean, but it can still find patterns.
- **B2, the oracle.** Does not read the note. It gets the true evidences straight from the dataset, essentially reading from the answer sheet. It marks the top of the ruler, so whatever it can't do, the other models can't do either.

**M-class: learned representations.** Each one ends in a small neural network (a one-hidden-layer MLP) trained on tier 0 only.

- **M1, SapBERT text-only.** A frozen biomedical language model reads the note, turns each word piece into 768 numbers, and averages them into one vector per patient. Only the small classifier on top learns. This is the text half of the hybrid.
- **M2, concepts only.** A dictionary tool (QuickUMLS) finds medical concepts in the note and returns their standard codes, CUIs. Each code gets a learned vector of 128 numbers, and those are averaged. This is the concept half of the hybrid.
- **M3, the hybrid.** M1's 768 numbers fused with M2's 128, with the same classifier on top. This is the model the whole project is about.
- **Soft-target** is a training setting, not a model. M1 soft-target and M3 soft-target are trained to surface the whole reference differential instead of putting the one true disease on top.

### The four versions of the text

The test patients never change. Only the words do. Models train on tier 0 only, so tiers 1 to 3 are wording they never saw. [The tiers →](/blog/medive-reference#the-four-tiers)

- **Tier 0, clean.** The templated note as written above.
- **Tier 1, synonyms.** Symptom names swapped for UMLS's own alternative names. Optional, and a bit circular since the concept pathway uses the same vocabulary.
- **Tier 2, lay language.** Symptom names swapped for everyday wording: "a belly that feels blown up like a balloon" for a bloated, distended abdomen. Two rewordings per symptom written by me, none of them in UMLS. This is the "realistic" case.
- **Tier 3, typos.** Letters swapped, dropped or transposed inside the symptom phrases, about one edit per ten characters. The extreme test.

### The scores

Each patient has one true disease and one reference differential. Every condition runs on five random seeds. [More details on scores →](/blog/medive-reference#the-scores)

Against the true disease:

- **Acc@k.** Is the true disease in the model's top k? Reported for k = 1, 3 and 5. Acc@1 is plain "accuracy".
- **MRR.** Mean reciprocal rank. First place scores 1, second place 1/2, third 1/3, averaged over patients. It rewards putting the right answer near the top even if it isn't first.
- **Macro-F1.** The F1 score at rank 1, computed per disease and averaged with equal weight. A rare disease counts as much as a common one, which plain accuracy doesn't account for.

Against the reference differential:

- **DDR@5.** Differential recall. Of the diseases on the reference list, how many made it into the model's top five? It has a ceiling of 65.7 percent on this test set, because the reference list has about nine entries and five slots can't hold nine. **DDR@10** is the same thing with ten slots.
- **DDP@5.** Differential precision. Of the model's top five, what share is on the reference list. High DDR with low DDP means the model found the list by guessing widely.

We can notice a few things:

### 1. Clean text is too easy to tell the models apart

The oracle (perfect model) scores 99.7 at rank 1, and the basic baselines are within a point of it. Every model puts the true disease in its top three, every single time. The question about relevance on clean text is going to be a tie, but that wasn't a surprise, since it's close to being the "perfect" scenario.

### 2. The differential diagnosis list is where one stands out

Every standard model here was trained to predict only the one true pathology, and each of them recovers somewhere between a third and 40 percent of the differential list. On the other hand, the soft-target model that was trained on the full list instead of the single true disease reaches 59.3 (the ceiling is 65.7) at the cost of Acc@1, which drops to 75.8. We can see that the quality of the results follows what we ask the model to learn.

### 3. The language model is the one that minds typos, not the keyword matcher

I was reasonably confident that the keyword matcher would suffer most from noise. The opposite happened.

| Condition | Acc@1, clean | Acc@1, typos | DDR@5, clean | DDR@5, typos |
| --- | --- | --- | --- | --- |
| B0 keyword match + LR | 98.8 | 98.7 | 40.1 | 39.0 |
| B1 TF-IDF + LR | 99.3 | 98.8 | 39.5 | 34.7 |
| M1 SapBERT text-only | 98.9 | 95.0 | <u>34.4</u> | <u>32.1</u> |
| M1 soft-target | 75.8 | 51.0 | 59.3 | 54.5 |

<img className="diagram" src={_figTypoDrop} alt="Acc@1 and DDR@5 per condition, clean versus typos, with the SapBERT conditions dropping the most" />

With typos, word counting still sees all the hundred other words, and fuzzy keyword matching forgives spelling by design, whereas SapBERT does neither, so it loses about four points at rank 1, where the baselines lose half a point or nothing.

The bigger drop is with M1 soft-target: 75.8 clean, 51.0 with typos, which is a loss of 25 points. It's the same model as M1, but what's different is the training goal. The soft-target model was trained to spread its probability across a whole differential diagnosis, so its top choice sits only slightly above the second and third. A typo translates to a small nudge to the input vector, and a small nudge is enough to flip which disease comes first. The single-label M1 was trained to put one disease far ahead of the rest (confidently), so the same nudge rarely changes the winner.

The right panel of the graph above explains this well. Looking at the differential scores, every standard model sits at around the same, much lower score: B0 at 40.1, B1 at 39.5, the oracle at 39.0, M1 at 34.4. Even the oracle, which reads the answer sheet, doesn't get past 40. The soft-target model starts at 59.3, drops about five points down to 54.5 with typos, and it's *still* fourteen points above the best of the others on *clean* text.

So the rank-1 pick is quite sensitive, not the list used for differential diagnosis.

## Poking around SapBERT's space

Since this is the first post, post is the fun one, here are a few more pictures. None of them are going in the essay as they stand, but each of them taught me something about the model I'm building on.

### The 49 diseases, two ways

SapBERT has never been told what our 49 pathologies are, and yet it can still place them, and in two different ways. The first way is to hand it the 49 pathology *names* and nothing else, which is close to what it was actually trained for. That gives the map below: 49 short phrases, squashed down to two dimensions with PCA (principal component analysis, which only rotates and flattens the cloud of points). PCA is the honest choice for a small set of points like this one, because it can only move the cloud around. It never invents a cluster that wasn't there.

<img className="diagram" src={_figDiseaseNames}
     alt="The 49 DDXPlus pathology names as SapBERT embeds them, PCA to two dimensions, one fixed colour per pathology" />

Names that share a word sit together: "stable angina" next to "unstable angina", the two rhinosinusitis, bronchitis next to bronchiolitis, the two neoplasms off on their own. This is SapBERT doing what it was built for.

The second way is to average each pathology's patient notes into one vector, and that's the view the classifier actually works with. To get both views onto one map, I rotated the cloud of note vectors onto the cloud of name vectors as well as it can be rotated. The technique is called Procrustes: centre both clouds, scale both, then keep the rotation that lines them up best. I drew the result through the same PCA as the names, so the two views share one set of axes. The left panel below is the notes sitting on the name map. The right panel is the same idea as the typo lines further down: one line per pathology, from where its name sits to where its patients sit.

<img className="diagram" src={_figDiseaseMaps}
     alt="Left: the 49 note centroids rotated onto the name map. Right: a line per pathology from its name position to its note position, the ten longest labelled" />

Even after the best possible rotation, the two clouds don't overlay. On a scale where 0 means the same arrangement and 2 means nothing in common, what's left over is {space.procrustes.disparity.toFixed(2)}. Another way to put it: on average, only {(space.views_agree.mean_neighbour_overlap * 100).toFixed(0)} percent of a pathology's five nearest neighbours are the same in both views. So the two views disagree about most of the neighbourhood.

The pathologies that move the least are the ones whose wording and symptoms agree: {space.procrustes.least_moved.slice(0, 3).map(m => m[0]).join(", ")}. The ones that move the most are {space.procrustes.most_moved.slice(0, 3).map(m => m[0]).join(", ")}, and that group turns out to have a reason of its own, which gets a section to itself below. First, why the two views differ at all. It comes down to what each dot is made of.

**A dot in the note view is an average of averages.** Each note is the mean of about {stats.wordpiece.pieces_mean_clean.toFixed(0)} word-piece vectors. Each pathology is then the mean of hundreds of those notes, which gives one dot per disease, its centroid. And every note shares the same template skeleton: "year-old patient", "presents with", "pain intensity", "travel out of the country". So all 49 centroids end up packed close together. Measured by cosine similarity (1 means pointing the same way, 0 means unrelated), the average pair scores {space.views_spread.notes_pairwise_cosine_mean.toFixed(2)}, and even the two *least* alike still score {space.views_spread.notes_pairwise_cosine_min.toFixed(2)}. What survives once the shared skeleton cancels out is the symptoms, so this view groups diseases by what patients say.

**A dot in the name view is one short phrase.** One to five words, nothing shared, nothing averaged. The names are spread far apart: average similarity {space.views_spread.names_pairwise_cosine_mean.toFixed(2)} against the notes' {space.views_spread.notes_pairwise_cosine_mean.toFixed(2)}, and the least alike pair is down at {space.views_spread.names_pairwise_cosine_min.toFixed(2)}. What this view keeps is the word overlap. SapBERT was trained to pull different names of the same concept together, and names that share a word are the easy case.

PSVT is the clearest case. It stands for paroxysmal supraventricular tachycardia, which is a heart that suddenly starts racing and then stops on its own. By the notes, it sits next to panic attack, since both arrive as a racing heart, chest discomfort and a frightened patient, and that's a confusion a clinician would recognise. By the name, it sits with the anginas and NSTEMI (a kind of heart attack), because those are the other cardiac words in the list.

Pneumonia splits the same way. By the notes it lands with the whole-body illnesses, influenza, HIV and SLE (lupus), which all bring fever, fatigue and aches. By the name it lands with anything that has a lung in it. Stable angina is the one case where the two views agree, because the diseases that share its wording happen to share its symptoms too.

So the note view is what the classifier gets to use: symptoms, with the template washed out. The name view is the ontology's view, sneaking in through the words themselves. It's also roughly the kind of structure the concept pathway is meant to add, since a concept code is closer to a name than to a note. Whether that helps M3 is the whole question, and I don't get to answer it in this post.

We can see that when the model is wrong, it's mostly wrong in the direction the space was already leaning.

So why do these particular pairs overlap? Here's my lay reading of it. I'm reading the dataset's symptom lists, not giving a clinical opinion.

- **Chronic and acute rhinosinusitis**, the biggest one, and it goes both ways. Same illness: inflamed sinuses, so a blocked nose, facial pain or pressure, discharge, a dulled sense of smell. What separates them is *duration*, weeks versus months, and a snapshot note has no duration in it. No amount of careful reading fixes that. The information isn't in the text.
- **Stable angina, unstable angina, NSTEMI/STEMI.** The same chest pain coming from the heart's blood supply, at three levels of urgency. What tells them apart is *when* the pain arrives, whether it comes on with effort and settles with rest or sits there getting worse, and whether heart muscle is actually being damaged, which takes an ECG and a blood test to know. None of that is in a symptom note. Clinicians don't separate these three from the history alone either. That's what the tests are for.
- **Bronchitis, spontaneous pneumothorax, and GERD.** Acid reflux brings chest pain, a burning feeling and often a cough. Bronchitis is a cough plus chest discomfort. A pneumothorax, which is air leaking around a lung, is sudden chest pain and breathlessness. So all three arrive with the chest words and little else. GERD is also one of the ten most frequent classes in the test set, which makes it the model's safe bet when the chest words are there and the rest is scrambled.
- **Boerhaave and GERD.** Boerhaave is a torn oesophagus after violent vomiting, and GERD is the same organ complaining much more mildly. Both notes carry vomiting and pain in the chest or the upper belly.
- **Acute laryngitis, viral pharyngitis, URTI.** Three names for a viral infection of the same few inches of throat, so all three give a sore throat, a hoarse voice, a cough and a bit of fever. Real triage lumps them together too.

The pattern is the same each time. A confused pair is either one disease caught at two stages, or two neighbouring organs sharing the template's pain block. And in both cases the fact that would decide it, a duration, a test result, one precise location, is either missing from the note entirely or living in a single clause. A single clause is exactly what a few typos erase. Whether these count as "reasonable" confusions is the error-analysis question for the essay, and it needs someone with clinical training to settle it.

## Where M1's four points go

### Looking inside the language model

BERT-family models and basically every Large Language Model (LLM) read *word pieces*, not words. The tokeniser used by SapBERT is called WordPiece, and it carries a fixed vocabulary of about thirty thousand pieces. Any word that isn't in that vocabulary gets split into the longest pieces it does know. A clean medical word is usually one piece, whereas a misspelled one won't be recognised at all. Here's SapBERT's own tokeniser on words from patient `test_12`, clean on the left, tier 3 on the right:

| Clean | Pieces | Typo | Pieces |
| --- | --- | --- | --- |
| significantly | `significantly` | signifcantly | `sign` `##if` `##can` `##tl` `##y` |
| cough | `cough` | couhg | `cou` `##hg` |
| symptoms | `symptoms` | sypmtoms | `sy` `##pm` `##to` `##ms` |
| heavy | `heavy` | hevay | `hev` `##ay` |

The `##` marks a piece that continues the previous one. Those fragments were never learned as "significantly" or "cough", so their vectors have nothing to do with the word the patient meant. M1 averages every piece's vector into one vector per patient. So every corrupted word pulls that average a bit off course.

The fragments also make the note longer: {stats.wordpiece.pieces_mean_clean.toFixed(0)} pieces on average at tier 0, {stats.wordpiece.pieces_mean_typos.toFixed(0)} at tier 3. SapBERT reads all of it, so nothing is lost off the end. The whole cost of a typo is that one word's vector goes wrong, and a note has a hundred other words to average it against. That's why the damage is four points and not a collapse. Tier 3 is a test of the tokeniser and the averaging, and nothing else.

### One word, one edit at a time

The cleanest version of the WordPiece story. Take a symptom word and apply one random character edit, then another, and so on. After each edit, measure how far its vector has moved from the clean word. The result is averaged over {space.word_typos.trials} random edit paths.

<img className="diagram" src={_figWordTypos}
     alt="Left: cosine distance of a word from its clean form against the number of character edits. Right: number of word pieces the tokeniser produces" />

## What got decided since devlog #0

A few things got settled in the two weeks since the plan. All of them before the hybrid model exists, and that's on purpose. It's a lot harder to fool yourself when the rules are written down first.

- **Two training goals, reported separately.** A model can learn to put the one true disease on top. Or it can learn to reproduce the whole reference differential. The second is called soft-target, and every hybrid result will be reported under both.
- **DDR@10 joins the scores** as a secondary metric. The reference differential has about nine entries, and five slots can't hold nine diseases.
- **Two comparisons are locked:** hybrid vs text-only, and hybrid vs TF-IDF. Each one on clean text, lay language and typos. Locking them now stops me from picking whichever comparison happens to look best later.
