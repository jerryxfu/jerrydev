## Adding a post

Two steps: append an entry to `posts` in `posts.tsx`, then create the matching file in `posts/`:

````ts
{
    slug: "why-rag-is-mid",          // must match posts/why-rag-is-mid.mdx
    title: "Why RAG is mid",
    description: "Card copy, and the meta description on the post page.",
    date: postDate("2026-09-01"),   // NOT new Date() (see below)
    tags: ["ai", "notes"],
    image: _ragDiagram,              // optional
    draft: true,                     // optional
}
````

Miss either half and the dev console names the offender at boot. Nothing enforces this at build time, so that check is the only safety net.

Use `postDate("YYYY-MM-DD")`, never `new Date("YYYY-MM-DD")`. A bare date string is parsed as **UTC** midnight, which
is the previous evening anywhere west of Greenwich. The helper appends `T00:00:00` to force local parsing.
Similar issue to ProjectCards.

## Headings start at h2

The `title` field renders as the page's `h1`. Starting a post with `#` produces a second `h1` and the page ends up with two competing titles.
Use `##` for top-level sections; `h2` through `h4` are styled.

## Tags are a closed set

Every tag has to exist in the `TAGS` array in `posts.tsx` before it can be used. That is deliberate so a typo becomes a `tsc` error instead
of a filter chip that silently matches nothing.

````ts
export const TAGS = ["devlog", "ai", "webdev", /*...*/] as const;
````

Declaration order is the order the chips render in on the list page. Tags with no posts get no chip at all.

## Drafts

Setting `draft: true` leaves the post in the list but renders the card dimmed, dashed and grayscale, with no link.
The route refuses the slug too, so typing the URL directly is a dead end.

Bypassed in dev.

> This is a soft gate, not privacy. The prose is compiled into the bundle and committed to a public repo either way.
> If something genuinely shouldn't be read yet, don't commit it.

## Images

Card images are static imports in `posts.tsx`, never string paths — that's what keeps them hashed, fingerprinted and in the right cache bucket.
Omit `image` entirely and the card runs its text the full width.

`image` also accepts a rendered element, which is what the card for this post uses:

````tsx
import {Mdx} from "@/assets/projects/mdx.tsx";

{
    slug: "hello-blog",
    image: <Mdx />,
}
````

That is the only reason the manifest is `posts.tsx` and not `posts.ts` — so the element form can be written as JSX
rather than as `createElement` calls. A raster asset crops to fill the thumbnail; a vector scales to fit it instead.

One consequence: an element cannot be an `og:image`, so a post whose image is a component falls back to the site's
default card when it's shared. Use an imported asset if the social preview matters.

Images inside the prose are centered automatically. Text stays left aligned.

## Code blocks

Fenced code is highlighted by Shiki at build time, so nothing ships to the browser except the coloured markup:

```python
def attention(q, k, v):
    scores = q @ k.T / (k.shape[-1] ** 0.5)
    return softmax(scores) @ v
```

Registered languages are `ts`, `tsx`, `js`, `jsx`, `python`, `bash`, `json`, `scss` and `java`. Adding one is a
one-line change in `vite.config.ts` and costs build time only.

**The gotcha:** an unregistered language does not fail the build. It renders as a plain unhighlighted block, exactly
like this one, and it is easy not to notice why:

```ruby
puts "ruby is not registered, so this is not highlighted"
```

A fence with no language at all does the same thing, which is sometimes what you want:

```
$ pnpm dev
```

Inline code uses single backticks and is styled separately.

## Maths

`remark-math` plus `rehype-katex`, rendered at build time. Inline maths goes between single dollars: the squared error
$\frac{1}{n}\sum_i (y_i - \hat{y}_i)^2$ sits in the sentence. Display maths goes between double dollars on their own
lines:

$$
\frac{\partial L}{\partial w} = -2X^\top(y - Xw)
$$

Environments work too, so `aligned`, `bmatrix`, `cases` and the rest are all available. Inside them `\\` is a genuine
line break — one of the few places a double backslash is correct rather than a mistake:

$$
\begin{aligned}
z &= Wx + b \\
\hat{y} &= \sigma(z)
\end{aligned}
$$

**The trap:** two dollar amounts in one paragraph get read as maths. Writing "it costs \$5 and then \$10 more"
without escapes turns *5 and then* into a formula. Escape them as `\$`.

KaTeX sets no colours of its own, so equations inherit the body text and follow the theme. Long display maths scrolls
sideways instead of widening the page.

### Syntax cheatsheet

Left column is what you type, right column is what it renders as.

| Write | Renders |
| --- | --- |
| `$x^2$` | $x^2$ |
| `$x_i$` | $x_i$ |
| `$x_i^2$` | $x_i^2$ |
| `$x^{2n}$` | $x^{2n}$ |
| `$\frac{a}{b}$` | $\frac{a}{b}$ |
| `$\sqrt{x}$`, `$\sqrt[3]{x}$` | $\sqrt{x}$, $\sqrt[3]{x}$ |
| `$\sum_{i=1}^{n} x_i$` | $\sum_{i=1}^{n} x_i$ |
| `$\prod_{i=1}^{n} p_i$` | $\prod_{i=1}^{n} p_i$ |
| `$\int_0^1 f(x)\,dx$` | $\int_0^1 f(x)\,dx$ |
| `$\alpha, \beta, \theta, \sigma, \lambda$` | $\alpha, \beta, \theta, \sigma, \lambda$ |
| `$\hat{y}, \bar{x}, \tilde{z}, \vec{v}$` | $\hat{y}, \bar{x}, \tilde{z}, \vec{v}$ |
| `$\mathbf{X}$`, `$\mathbb{E}$`, `$\mathcal{L}$` | $\mathbf{X}$, $\mathbb{E}$, $\mathcal{L}$ |
| `$X^\top$` | $X^\top$ |
| `$\partial$`, `$\nabla$` | $\partial$, $\nabla$ |
| `$\text{loss}$` | $\text{loss}$ |
| `$\cdot, \times, \approx, \leq, \neq$` | $\cdot, \times, \approx, \leq, \neq$ |
| `$\to, \implies, \in, \infty$` | $\to, \implies, \in, \infty$ |
| `$\left\| x \right\|_2$` | $\left\| x \right\|_2$ |

Three things that catch you out:

- **`\,` is a thin space.** LaTeX ignores ordinary spaces in maths, so `\int_0^1 f(x) dx` sets the `dx` flush against
the function. `\,` is how you get the gap.
- **A bare `|` inside a table breaks the row.** GFM reads it as a cell divider before maths ever sees it, so the
equation silently renders as plain text. Norms and absolute values need `\|`, as in the last row above.
- **`\\` is a line break, not an escape.** It belongs inside `aligned` and nowhere else. `\\frac` is always wrong.

Multi-line derivations use `aligned`, with `&` marking the alignment point:

````latex
$$
\begin{aligned}
\mathcal{L}(w) &= \frac{1}{n} \sum_{i=1}^{n} (y_i - w^\top x_i)^2 \\
\nabla_w \mathcal{L} &= -\frac{2}{n} \sum_{i=1}^{n} x_i (y_i - w^\top x_i)
\end{aligned}
$$
````

$$
\begin{aligned}

## Arbitrary JSX

This is MDX, so components and markup drop straight in. Import at the top of the file:

````jsx
import {Mdx} from "@/assets/projects/mdx.tsx";

<Mdx />
````

Which renders: <Mdx />

### The import at the top of this file is load-bearing (crucial)

WebStorm greys it out as unused. It parses the ESM block as TypeScript but does not trace the reference down into the
markdown body, so the import looks safe to delete. **It is not**. Removing it throws `Expected component Mdx to be defined`
and points at the *usage* line, never at the line that is missing!

**There is no in-file suppression that works.** `// noinspection ES6UnusedImports` above the import is parsed as
markdown, so it renders as visible text in the post *and* swallows the import into the same paragraph, breaking it.
Put it below the import and it stays invisible but suppresses nothing, since `noinspection` applies to what follows it.

Possible fix: in the IDE exclude `*.mdx` from Unused import checks.

### Custom blocks

Anything self-contained works inline too, and theme variables resolve normally, so a custom block follows the theme toggle instead of fighting it:

<div style={{
    padding: "1.5rem",
    borderRadius: "10px",
    background: "linear-gradient(135deg, var(--primary-ltx), var(--secondary-lt))",
    color: "var(--text-strong)",
    textAlign: "center",
}}>
    Custom background, defined entirely inside this post.
</div>

Three MDX parsing traps, all from markdown and JSX disagreeing about what a line is:

- A bare `{` in prose is read as the start of an expression. Wrap it in backticks.
- So is a bare `<`, which is why `posts/<slug>.mdx` has to be written in backticks or it parses as a JSX tag.
- A markdown comment (`[//]: # (...)`) on the line **directly above** an import absorbs it as a lazy continuation, so
the import silently becomes prose and every component in the file breaks. Leave a blank line between them.

````ts

    title: "*.jerryxf.net",
    description: "This portfolio website, the blog, as well as the API that empowers other projects.",
    blogSlug: "hello-blog",
}
````
